# AGENTS.md

Guidance for AI coding agents working in this repository (this checkout = `openrecall` fork on the `local` branch, **Arch Linux + KDE Plasma (Wayland)**).

## Environment

- OS: **Arch Linux**, KDE Plasma on **Wayland**; shell is bash.
- Python: use the repo venv — `.venv/bin/python` (this checkout's venv is Python 3.14). Never rely on system Python.
- Wayland session; `qdbus6` (not `qdbus`), `gdbus`, `dbus-send`, `busctl`, `kscreen-doctor`, `journalctl`, `pactl`/`pw-cli` are available. Python `dbus` is **not** installed (see Gotchas) — use the `gi` (Gio/GLib) backend that ships with the wayland package.
- Storage default: the platform convention — Linux `~/.local/share/openrecall` (override with `OPENRECALL_STORAGE` or `--storage-path`).
- Storage paths contain regular names but may hold unicode screenshot content; quote paths.

## Commands

- Tests (current: 74 passing):
  - `.venv/bin/python -m pytest tests -q`
- No linter/formatter is configured. After editing, at minimum byte-compile the touched modules:
  - `.venv/bin/python -X utf8 -c "import py_compile; [py_compile.compile(f, doraise=True) for f in ['openrecall/app.py']]"` — list each changed file.
- Run services:
  - `systemctl --user status openrecall-capture openrecall-web openrecall-ai` — the live stack.
  - `journalctl --user -u openrecall-capture -f` — follow capture output.
- One-off probes: run `.venv/bin/python -X utf8 -c "<code>"` from the repo root (the package imports as `openrecall`).

## Services (systemd --user)

| Unit | Purpose |
|---|---|
| `openrecall-capture.service` | The **only** capture process: `python -u -m openrecall.screenshot`. Owns the KWin active-window bridge, heartbeat/AFK logic and the rich Linux sources. |
| `openrecall-web.service` | Flask web UI/API on `http://localhost:8082`. Runs **web-only** (`OPENRECALL_DISABLE_CAPTURE=1`) so it never double-captures. |
| `openrecall-ai.service` + `openrecall-ai.timer` | Headless `bulk_summary.py` run on a timer. |
| `ollama.service` | Local model server (`~/.local/bin/ollama`). |

Both capture and web units set `WAYLAND_DISPLAY`, `XDG_SESSION_TYPE=wayland`, `XDG_CURRENT_DESKTOP`, `OPENRECALL_STORAGE`, and `PYTHONUNBUFFERED=1`. `OPENRECALL_SESSION_MIN_LEN_MINUTES=0` on the web unit so the current session is visible immediately.

## Storage & database

- Data root: defaults to `~/.local/share/openrecall`; override via `OPENRECALL_STORAGE` or `--storage-path`.
- `recall.db` (SQLite) at the data root; screenshots in `screenshots/`; AI output in `summaries/`; rich-source log `linux_snapshots.jsonl`; `wallpaper_reference.webp` (desktop art reference).
- `entries` table columns (in `Entry` namedtuple order): `id, app, title, text, timestamp, embedding` (BLOB float32), `filename, monitor, screen_x, browser_url, browser_tabs` (JSON), `windows` (JSON).
- `UNIQUE(timestamp, monitor)` — one row per monitor per moment.
- `openrecall/database.py` owns the schema; `create_db()` auto-migrates older DBs in place via `ALTER TABLE`.

## Capture data model

- A **moment** = all monitors at one timestamp. MSSIM ≥ 0.9 similarity decides which screens "changed"; only changed screens get a fresh screenshot/OCR/embedding, the rest reuse their last file/text/embedding.
- OS context is **per screen** (not duplicated across rows):
  - `browser_tabs`: the ACTIVE (on-top) tab — title + URL + 0-based `monitor` index — of each visible browser window. One per window; background tabs are never recorded.
  - `windows`: app + title + `monitor` of every visible window, plus `active` and `fullscreen` flags (KDE). Minimised/off-screen windows carry `monitor: null`.
  - `get_top_window_per_monitor()` gives the per-screen active app/title used for that row's `app`/`title` columns.
- Monitor indices match the compositor's monitor order (0-based).

## Gotchas

- **KDE window order**: `get_windows_kde()` sorts windows *topmost-first* (not-minimized → focused → fullscreen → higher layer) so `get_top_window_per_monitor()` (which keeps the FIRST window covering a screen) attributes a fullscreen game/focused app correctly. KWin's window list has no z-order, so the focus bridge (`kde_active.py`) supplies the active flag.
- **Active-window bridge is single-owner**: `org.openrecall.KWinBridge` can be owned by one process only. `openrecall-capture.service` owns it; a second process (e.g. an ad-hoc probe) cannot register the name and will see `get_active_window() -> None`. Stop the service if you must probe it.
- **Python `dbus` is not installed** (`DBUS_AVAILABLE = False`), so any `linux_sources` helper that uses `_get_session_bus()`/`_dbus_call()` is a no-op. Window lists and virtual desktops go through the Gio-based `openrecall.wayland` backend instead.
- **KWin screenshots**: the `org.kde.KWin.ScreenShot2` DBus API returns `NoAuthorized` for non-Spectacle callers → capture full-screen via `spectacle -f -b -n -o` and split per-monitor by geometry.
- **Monitor geometry**: `kscreen-doctor -j` flags **no** mode as `current`; read `pos` + `size`. Skip mirrored outputs (`replicationSource != 0`); `OPENRECALL_IGNORE_MONITORS` (comma-separated names) drops specific monitors.
- **mss monitor dicts only have `left/top/width/height`** — map windows→screens via `utils.monitor_rects()` / `utils.monitor_for_rect()`, never derive right/bottom yourself.
- **Browser tabs need Remote Debugging**: Firefox/LibreWolf must be launched with remote debugging (`--start-debugger-server 6000`) or tab capture returns empty. `browser_url_linux.py` degrades gracefully.
- **Session model** (`openrecall/sessions.py`): session = run of moments with no gap > `SESSION_GAP_HOURS` (default 2h, `OPENRECALL_SESSION_GAP_HOURS`); `SESSION_MIN_LEN_MINUTES` (default 10) hides micro-runs. `get_entries_for_session`/`get_entries_between(..., inclusive_end=True)` include the last moment. Prune must use `min_len_minutes=0`.
- **Capture boundaries**: active = heartbeat moment every 5 min; AFK = only real screen changes write a moment, so a static overnight desktop yields nothing and the 2h gap becomes the boundary. `OPENRECALL_SIMILARITY_THRESHOLD` (default 0.75, looser than upstream).
- **Wallpaper screens** matching `wallpaper_reference.webp` (≥ `WALLPAPER_SIM_THRESHOLD`, default 0.90) or with no window attributed are never sent to the model; their `Screen contains no meaningful content.` blocks are written in code.
- Prune/ad-hoc `pkill` patterns: use `pkill -f "ollama serv[e]"` so the pattern doesn't match the invoking shell.
- Scratch probe scripts live under `/tmp/opencode/` when used ad-hoc — don't commit them into the repo.
- Never commit unless the user explicitly asks. Keep working changes on `local`; `main` tracks upstream and must stay clean.
